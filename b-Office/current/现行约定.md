# HistoryMercury 现行约定

本仓唯一的长期文档。这里只写**从代码和测试里看不出来的项目元数据**；做法以代码为准，
每版做了什么看 `git log`。条目被推翻就直接改掉，不留历史。

## 真相在哪

| 要知道的 | 去哪看 |
| --- | --- |
| `mercury.*` 指令怎么调用 | 注册自描述：`diana.docs.read domain=mercury`；改指令后 `diana.docs.audit domain=mercury` 零缺陷 |
| 代码面（`HistoryMercury.dll`） | 随包的 `HistoryMercury.xml`；公开类型缺 summary 由 Smoke 拦 |
| 页面长什么样 | `Ui/MercuryPages.cs` 里的页面描述；组件写法问 Aurora：`aurora.component.show name=<名>` |
| 行为是否成立 | `b-Code-Tests/HistoryMercury.Smoke`，测试注释写着每条规矩为什么存在 |
| 版本与宿主下限 | `b-Code-MercuryDock/HistoryMercury.csproj` 的 `Version`（程序集版本的唯一来源） |

## 取舍

- **桌面坞是本模块自己的窗口，不是页面。** 模块一装上就在自有 STA 线程上显示，前端关着也在；点 `HC` 磁贴才唤起前端。它不查前端主题，颜色字号自己拿着。
- **页面只声明 `dock.manager`，`scene=HistoryMercury`。** 用户已保存的各场景布局（分栏、位置、比例、隐藏）优先；模块刷新不得打开或改写别的场景的页面。命令集页归 Aurora，本模块不再声明第二页。
- **版面预算优先于可发现性。** 管理页没有页首说明、表格不上「最近打开」列、六条行操作全部只在右键。版面上没有任何东西提示右键有内容，这是取舍，不是漏了提示。
- **按钮绑动作 id，不绑指令名。** 三条 `mercury.ui.*` 与 `mercury.dock.run` 不对远端暴露：前者是界面内部协议，后者会代为执行坞里登记的指令文本。
- **`mercury.go` 是唯一的两段直接方法**，用来聚焦或退出控制台域。双斜杠快捷键执行 `vulcan.app.focusconsole`，不是 `mercury.shortcut.wakeconsole`。
- **可变数据只写宿主给的数据目录。** `%AppData%\HistoryVulcan\Modules\HistoryMercury` 是只读运行包，往里面写文件会让下一轮发现判成坏包。
- **最低宿主 HistoryVulcan 6.0.0。** 页面要 HistoryAurora ≥ 1.21.1（场景隔离）。面板协议 V3 的 `rows` 自 Aurora 1.9.2 起就是硬下限：更早的前端会把工具条和「加入扩展坞」画成空面板，而且不报错。

## 真机才知道的

- **热重载先拆后装，桌面会空出大约 0.3 秒**，这不是故障。建窗必须排在资源管理器注册之前，否则这段空白会拉到大约 1.8 秒。`Attach` 要等到坞就绪（上限 10 秒），否则下一轮拆除可能留下关不掉的孤坞。无头 Smoke 建不了窗，盖不住这件事；验收看日志里的「桌面坞已就绪」，以及重载全程坞数不超过 1、完成后恰好为 1。
- **生效的是已安装的运行包，不是已提交的源码。** 协议下限改了却没装上去时，页面会变成空面板，两边都不报错。

## 工程约定

- 发版改三处版本号：`HistoryMercury.csproj` 的 `Version`、`module.manifest.json`、`project.manifest.json`。漏改 `module.manifest` 时宿主静默跳过整个模块，界面上就是坞和管理页一起消失。
- 生产源码在 `b-Code-MercuryDock`，按 `Module`、`Commands`、`Dock`、`Explorer`、`State`、`Ui`、`Input`、`Diagnostics` 分组。Smoke 在 `b-Code-Tests/HistoryMercury.Smoke`，不得嵌回生产目录。
- 项目合同校验在宿主进程内管线，本仓 `commands.verify` 为空。候选由 `vulcan.dev.submit` 构建并热装，本仓不自行发布。
- 不留 `history/`、方案、需求书。仍有效的结论写进本文、调用处注释或 Smoke。
