# HistoryMercury Active Decisions

1. The visible module name, assembly name, manifest name, runtime slot, and formal snapshot name are all `HistoryMercury`.
2. `Mercury` is reserved for source namespace and the lowercase command domain. Business commands use `<domain>.<class>.<method>`; `mercury.go` remains the intentional two-part direct method for domain focus. The compatibility command `mercury.shortcut.wakeconsole` remains registered, while the `//` shortcut targets the stable Vulcan semantic command `vulcan.app.focusconsole`.
3. Commands are a hard cut: `dock.*` and `mercury.dock.open` are not registered alongside the new names.
4. The composition-root path `IModuleContext.RegisterCommands` is the only business-command registration path. UI command candidates reuse that catalog; there is no independent alias list.
5. Old `MercuryDock` and `ActiveDock` data are migration sources only. New writes use the `HistoryMercury` runtime and module slot.
6. Historical documents retain the names and command texts valid at the time they were written. Current contracts and consumer documents describe the HistoryMercury 4.3.0 candidate (owns global shortcuts and the Vulcan command workbench UI).
7. From 4.1.0, `GlobalShortcutService` and CommandSurface live in this module; HistoryVulcan keeps only Core contracts plus the console log surface.
8. Candidate creation is automatic after validation; promotion to the formal `z-HistoryMercury` snapshot requires an explicit approved release and a clean committed source tree.
9. Completion uses one domain -> class -> method -> parameter engine. Matching is case-insensitive exact, prefix, then contains; `Position=0` parameters accept the bare `method value` form, while named-only parameters retain `name=`.

## DEC-009 V4.2.0 域聚焦入口、无类直接方法与活动坞磁贴改色

- 状态：已接受
- 日期：2026-08-10
- 决策：分三条。
  1. **`mercury.go` 是域聚焦的唯一入口**，注册为本域的**无类直接方法**（两段名
     `mercury.go`，不声明 CommandClass）。`mercury.go <域>` 进入聚焦，
     `mercury.go` 无参退出。聚焦状态存放在共享的命令目录会话里，
     与 HistoryVulcan 控制台的域筛选下拉同源，两者自动同步。
  2. **命令名补全按域 → 类 → 方法 → 参数分段推进**。参数候选只取模块注册时提供的
     `ParameterSpec`，Mercury 不猜测参数名。域清单从传入的已注册命令定义现算，
     不硬编码。沿用既有的 Shift+W/S 选择与 Tab 确认。
  3. **活动坞磁贴改为白底圆角矩形 + 深黄文字，去掉光晕**。底色随使用频率由
     `#FFFFFF` 线性趋近 `#FAF0D8`，文字恒为 `#A87A12`；三个色值都取自
     HistoryVulcan UI 规范的 `Shell.Brush.Surface` / `AccentSoft` / `Accent` 浅色值。
- 原因：
  1. 退出聚焦若由各域自备指令，会让每个模块都耦合一条与自身业务无关的命令。
     宿主 DEC-025 的「首段命中已注册域即按绝对名解析」使 `mercury.go`
     在任何聚焦状态下都可直接输入，退出能力因此自然涌现，无需任何域配合。
     它切换的是控制台状态而非某类业务对象，所以不隶属任何类。
  2. 平铺全名候选在命令数上百后无法用键盘快速定位；分段推进让每一步的候选集
     都只有个位数到十几个。
  3. 光晕用模糊半径表达频率，在深色桌面上既不易分辨也会糊掉图标边缘；
     底色深浅是更直接的量度，且白底深黄文字在任意桌面壁纸上都可读。
- 后果：
  - 磁贴不再使用 `ProjectIconGenerator` 生成的缓存 PNG（底色需随频率实时变化，
    按名字哈希缓存的位图表达不了）；`ShortLabel` 提升为公开方法供磁贴取短标签。
    图标生成器本身保留，仍供资源管理器快捷方式使用。
  - `DockWeight.GlowOpacity` / `GlowBlur` / `MaxGlowOpacity` / `MaxGlowBlur`
    由 `TileTint` 取代。
  - Mercury 指令数 18 → 19，其中 1 条为无类直接方法。
- 替代条件：若 Mercury 的直接方法超过 5 条，应按 DEC-025 的替代条件评估是否建类。
