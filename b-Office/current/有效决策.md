# HistoryMercury Active Decisions

1. The visible module name, assembly name, manifest name, runtime slot, and formal snapshot name are all `HistoryMercury`.
2. `Mercury` is reserved for source namespace and the lowercase command domain. Business commands use `<domain>.<class>.<method>`; `mercury.go` remains the intentional two-part direct method for domain focus. The compatibility command `mercury.shortcut.wakeconsole` remains registered, while the `//` shortcut targets the stable Vulcan semantic command `vulcan.app.focusconsole`.
3. Commands are a hard cut: `dock.*` and `mercury.dock.open` are not registered alongside the new names.
4. The composition-root path `IModuleContext.RegisterCommands` is the only business-command registration path. UI command candidates reuse that catalog; there is no independent alias list.
5. Old `MercuryDock` and `ActiveDock` data are migration sources only. New mutable writes use the `%APPDATA%\HistoryVulcan\HistoryMercury` data root; the `Modules\HistoryMercury` runtime package is immutable.
6. Historical documents retain the names and command texts valid at the time they were written. Current contracts describe HistoryMercury 5.0.2.
7. From 4.1.0 the global shortcut host lives in this module. The command workbench also lived here from 4.1.0 to 4.8.1; HistoryVulcan 5.0 removed its mount point and the console now belongs to HistoryAurora (DEC-018).
8. Candidate creation is automatic after validation; promotion to the formal `z-Publish` snapshot requires an explicit approved release. Default is deploy-then-commit (dirty source allowed). Use `-RequireCleanSource` only to reproduce from a clean HEAD. The generated consumer mirror records `sourceDirty`.
9. Pages are data. The module declares them through `mercury.ui.describe` / `mercury.ui.actions` / `mercury.ui.data` and builds no frontend control of its own; the desktop dock is not a page and stays code-built (DEC-018).
10. Buttons bind action ids, never command names. Renaming a command changes one line in the action declaration and nothing on the page side.
11. The page description tracks the frontend's current rules, not the rules it was written against. Aurora's breaking
    changes fail silently on this side, so each one gets a smoke gate rather than a note (DEC-019).

## DEC-020 V5.0.2 版面预算优先于可发现性，改完必须发出去才算数

- 状态：已接受
- 日期：2026-08-30
- 背景：用户报「顶部那条状态栏没了」。查下来不是新的回归：5.0.1 之后已经按 Aurora 1.9.2 的
  面板协议 V3 把两个面板从 `widgets` 改成 `rows`，但那次改动只提交没发布，运行中的运行包
  还是 8/28 那份平铺 `widgets`。Aurora 拿到空 `rows` 判它合法，于是工具条和加入浮层
  都画成空面板——**源码是对的，运行的是错的**，而两边都不报错。
- 决策：三条。
  1. **发布才是交付。** 涉及协议下限的改动，验收看已安装运行包的版本与行为，不看提交。
     本轮把 V3 连同下面两项一起以 5.0.2 发出去。
  2. **版面预算优先于可发现性。** 页首说明、「最近打开」列、行内按钮列（Aurora 的「操作」列）
     三样一起去掉：页面不滚，省下的每一行、每一列宽度都直接变成条目表看得见的内容。
     右键的可发现性因此彻底没有了——这是明知代价后取的舍，不是遗漏。DEC-019 当时写的
     「页首说明必须写出来」由本条取代。
  3. **「不上表」与「不取数」分开。** `lastopened` 仍由取数产出：行操作占位符按被点那一行的
     同名列取值，把列从取数里删掉会让一条动作静默发空值——那正是 5.0.1 花了一整轮消灭的形态。
- 后果：
  - 对 HistoryAurora 的运行期下限确认为 **1.9.2**（面板协议 V3），且是硬下限。
  - 管理页六条行操作全部只在右键菜单里；表格只剩 名称 / 类型 / 状态 / 指令 / 权重 / 点击 六列。
  - 命令面、指令名、动作 id 与取数列**一个都没动**：这一版只改描述与版本。

## DEC-019 V5.0.1 页面跟上前端的收紧，缺的触发方式向 Aurora 提而不是自己绕

- 状态：已接受
- 日期：2026-08-28
- 背景：用户报了三件事——管理页顶上的内容竖排、坞上有些项目标题右边莫名多一个点、
  「mercury 下面的控件失效了」。查下来第一件和第三件是同一个根因：本模块的页面描述停在
  Aurora 1.7 的口径，而前端已经走到 1.9.1。
  - 1.8.14 把 `button` / `input` / `select` 整类退役出页面节点（连同页面按钮的
    `invoke` / `enabledWhen`）。5.0.0 在表格下面排了 7 个 `type: "button"`，
    **全部渲染成写着退役原因的牌子**——这就是「控件失效」；
  - 1.9.0 起页面不滚、装不下就裁掉。顶上两块竖排面板占掉的高度，直接就是条目表看不见的行；
  - 1.9.0 同时记账：表格的 `view` 是空转声明，写了没有任何效果。
  三条的共同点是**都不报错**。模块这边编译通过、烟测全绿、日志干净，只有人去点才知道。
- 决策：四条。
  1. **行操作走 `rowActions`，不再靠「选中 + 表下按钮」。** 一份声明同时给出行内按钮与
     右键菜单，占位符取被点那一行的同名列。行内只留「打开」「固定」，其余四条
     `inline: false` 只进右键菜单。
  2. **版面横排，加入面板移出版面。** 收录策略与刷新收成一条横排工具条；
     「加入扩展坞」改成右键弹出层。判据是频率与高度之比——它是这一页最高的一块，
     一周却用不到一次，而页面不滚之后它占的高度就是别人看不见的行。
  3. **缺的触发方式向 Aurora 提，不在本仓绕。** 「右键弹出一个带输入框的面板」当时不存在：
     仓里三处右键实现（表格行菜单、轮换选项框候选菜单、控制台复制菜单）都是**动作菜单**，
     放不进输入框。但浮层本体（`popup`）是现成的，缺的只是一个不占版面的开关。
     于是走 Aurora 的公共组件区加了 `popup.trigger`（Aurora 1.9.1 / REQ-UI-056），
     **没有新建组件**，浮层本体一行不动——这是 DEC-005「不自建组件、但必须有出口」的走法。
     本仓因此对 HistoryAurora 有了一条**运行期下限 1.9.1**；装在 1.9.0 上时 `trigger`
     被忽略，弹出层退回自带按钮，功能不丢、只多占一行。
  4. **每条收紧配一条烟测门禁，不写成注意事项。** 注意事项拦不住下一次——
     5.0.0 那 7 个按钮不是没人知道规则，是没有任何东西在改完之后说话。
- 后果：
  - 坞上的置顶标记从编号后追加 `"  ·"` 改成磁贴上的一圈亮黄描边（`DockTheme.PinnedRing`）。
    那个点不解释自己是什么，用户看见的就是「莫名多了个点」。描边**恒占 2px 只换颜色**：
    只在置顶时加边框会让磁贴内容区差 4px，而字号是按内容区算的，同一个项目一置顶字就变小。
  - 页首说明必须写出「右键页面空白处加入新条目」——右键弹出层的代价就是看不见。
  - 命令面、指令名、动作 id 与取数列**一个都没动**：这一版只改描述与坞的画法。

## DEC-018 V5.0.0 对齐宿主 5.1 与描述化前端：模块不再构造界面

- 状态：已接受
- 日期：2026-08-25
- 背景：HistoryVulcan 5.0 拆除了宿主的模块领域 SDK——`IUiModule` / `IShellUiAware` /
  `IShellUiRegistrar` / `IShellCommandWorkbenchAware`、`Core.Docking` 与整个
  `HistoryVulcan.Extensibility` 程序集全部删除，`IModuleContext` 只剩 `Bus` 与
  `RegisterCommands`。HistoryAurora 同轮把前端改成**描述化**：模块提交 JSON 描述，
  Aurora 用自己的组件库渲染。Mercury 4.8.1 的三处前端页（扩展坞管理、命令集、指令详情）
  和整个 `CommandSurface` 都建在已删除的契约上，编译都过不去。
- 决策：五条。
  1. **模块入口只剩 `Attach` 与 `Dispose`。** `MercuryUiModule` 更名
     `MercuryModule`，实现 `IModuleContextAware` + `IDisposable`。`CreateUi` /
     `DestroyUi` 及其两处注册一并删除。宿主在拆除阶段按 `IDisposable` 回收实例，
     因此关坞、停监视、收快捷键钩子都挪进 `Dispose`——4.x 里 `HotkeyService.Stop`
     实际上没有任何调用方。
  2. **页面改成数据，并自己发上行通知。** `Mercury.Ui.MercuryPages` 产出页面描述与动作声明，
     `Mercury.Ui.MercuryUiData` 产出行数据，模块**一个 WPF 控件都不构造**。
     `mercury.ui.describe` / `ui.actions` / `ui.data` 三条命令是本模块与前端之间的
     全部接口。DEC-005「模块不得自建组件」从此是结构上的事实：模块里连编译后的
     XAML 都没有（烟测断言 `HistoryMercury.g.resources` 不存在）。
     页面因此是派生状态，坞一变就旧，所以状态变化合并 300ms 后发一条
     `aurora.ui.invalidate owner=HistoryMercury`——模块只说「我变了」，
     由 Aurora 决定怎么重建，宿主仍然不解释任何界面语义。
  3. **桌面坞不受影响，仍然自持。** 它是 Mercury 自己的窗口而不是前端里的一页
     （DEC-017），代码构造、跑在自有 STA 线程上，与描述化协议无关。
  4. **命令工作台退场。** `CommandCatalogSession`、`CommandCompletionEngine` 与两处
     工作台视图删除：宿主 5.0 删掉了 `IShellCommandWorkbenchHost` 这个挂接点，
     控制台连同它的域筛选、补全与命令集页一起归 HistoryAurora。
     `mercury.go` 保留，改为在总线上转发 `aurora.log.source`——那是控制台域筛选的
     唯一写入口，`ConsoleView` 用同一个值做 `DomainFocus.Resolve`，语义不变。
     命令集以描述化页面的形式回来一页，数据取自 `vulcan.command.list`；
     **指令详情页没有回来**，见「未决」。
  5. **远端可见性由模块自己声明。** 5.0 之后 MCP 投影归 Portunus，宿主不再替模块
     判断暴露面，唯一依据是描述符的 `HiddenReason`。三条 `ui.*` 与 `mercury.dock.run`
     因此各自写明不暴露的原因。
- 原因：宿主替模块定义世界，就会永远替认领方再实现一套停靠和投影（Vulcan DEC-052）。
  代价这一轮全部落在 Mercury 身上：四条消费通道里只有「接口实现」受编译器保护，
  另外三条（`ContentFactory` 返回值、`DynamicResource`、pack URI 直连）都是运行期才炸，
  而 4.5.1 与 4.7.0 两次事故正好各出在其中一条上。改走描述之后这三条不再存在。
- 后果：
  - 命令 26 → 31：新增 `mercury.ui.describe` / `ui.actions` / `ui.data`、
    `mercury.dock.run`（页面按钮的「打开」落点，只接受当前坞里确实存在的行键，
    不接受任意指令文本，否则它就成了绕过逐条排除的旁路）与 `mercury.shortcut.pick`
    （把旧管理页「浏览 → 填回输入框 → 加入」三步收成一条：协议里没有
    「把指令结果写回控件」的表达）。
  - 公开面删除 `MercuryUiModule`、`MercuryManagerView`、`CommandSurfaceFeature`、
    `CommandCatalogSession`、`CommandCompletionEngine`、`CommandCatalogItem`、
    `CommandOptionTree`，因此走主版本号 5.0.0。
  - 模块日志改为自持（`Mercury.Diagnostics.MercuryLog`，落 `<数据根>\logs\`）：
    `IModuleContext` 不再注入日志，而总线上没有写日志的指令。
  - 引用面从三个宿主程序集降到两个：`HistoryVulcan.Extensibility` 已不存在，
    `Services` 仍然要（命令目录行类型）。
  - `Test-ProjectContract.ps1` 删除、`commands.verify` 置空：合同规则本体已迁进宿主的
    进程内开发管线（`HistoryVulcan.Services.Development.Pipeline.ProjectContract`），
    Diana 那份共用脚本随之消失，本仓再没有可独立运行的合同入口。
- 未决：**指令详情页**在页面协议 V1 里表达不出来——取数参数是静态的，
  没有「随另一个组件的选中行重新取数」的表达。它不是缺组件，是缺一条联动语义，
  因此没有登记成缺件，而是记在这里等协议 V2。

## DEC-017 V4.7.0 桌面坞是 Mercury 自己的界面，不是前端里的一页

- 状态：已接受
- 日期：2026-08-20
- 决策：三条。
  1. **桌面坞在 `Attach` 阶段起在本模块自有的 STA 线程上**，与前端在不在、开没开无关。
     判据从「进程里有没有 WPF Application」换成「本模块能不能开出一条 STA 线程」。
     快捷方式文件夹的监视与资源管理器入口注册一并挪到这条线程上——它们是坞的组成部分。
     `CreateUi` 只剩管理页与命令工作台两处**前端内**扩展，前端缺席时整段不发生。
  2. **`DockTheme` 的字体与间距自己拿着**，不再查 `Application.Current.TryFindResource`。
     取值与 `Aurora.Font.*` / `Aurora.Space.ControlPad` 一致，但坞在前端起来之前就要显示，
     不该跟着前端的主题走。
  3. **视图不得在本地合并 Aurora 的样式字典**（DEC-011 的重申与收紧）。管理页与两处工作台
     视图一律用 `DynamicResource` 沿可视树取宿主界面的资源，模块的 BAML 里不得出现
     `HistoryAurora` 的 pack URI。
- 原因：DEC-008 之后前端成了宿主装载的模块，在宿主进程内开窗时**刻意不建 WPF Application**
  （少一个进程级单例，也就少一处重载障碍）。坞的旧判据 `Application.Current == null` 因此恒真，
  坞永远不建——桌面上什么都没有，日志里一行错误也没有。这是 DEC-013「桌面坞不作为扩展的下游」
  同一条原则的第二次违反：上一次坞是排在工作台之后被异常带走，这次是整条 `CreateUi` 都不再发生。
  坞是唤起前端的入口，任何形式的「坞依赖前端」都会让前端一关就再也叫不回来，所以这次把依赖
  从顺序上的（谁排在谁后面）改成结构上的（坞根本不在那条链上）。
  第 3 条是同一轮暴露的另一个缺陷：管理页合并了 `AuroraControls.xaml` 却引用 `Aurora.Text.*`，
  而后者定义在 `AuroraTokens.xaml`，于是 `StaticResource` 解析失败，整个管理页在注册时抛
  `StaticResourceExtension` 异常，宿主只记一行 Warn。本地合并的作用域看着完整、实际只有一半，
  而 `DynamicResource` 没有这个陷阱：取不到就不套样式，不会把页面炸掉。
- 后果：命令集不变，仍为 26 条。`MercuryUiModule` 新增 `StartDesktopDock` / `RunDock` /
  `StopDesktopDock` 与只读的 `IsDesktopDockRunning`；`DestroyUi` 负责关窗、停 Dispatcher 并收线程，
  否则可回收上下文卸载时坞还在跑它自己的类型。`DockTheme` 去掉 `Find` / `FindDouble`。
  三份 XAML 去掉合并字典，23 + 10 + 1 处 `StaticResource` 改为 `DynamicResource`；
  模块 DLL 中 `HistoryAurora` 的出现次数由 3 降为 0。
  4. **重载后桌面上恰好一个坞，就是新的那个**。宿主的热重载是「先拆旧界面并卸载可回收
     上下文，再装新包」（`ModuleHost.Reload.cs`，为 WPF 模块刻意如此：先 Build 会让进程里
     同时存在两份同名程序集，新窗口的 XAML 随即解析失败）。这个次序天然排除了新旧两坞并存，
     Mercury 只需保证自己拆得干净、起得快。
     `Attach` 因此等待坞的就绪信号（上限 10s）：不等的话，下一轮拆除可能撞上还没建完的窗口，
     `StopDesktopDock` 看到 `_window` 为 null 什么都不关，随后建出的窗口再没人持有引用，
     桌面上就多一个关不掉的坞。
     不采用 `pinned: true`：钉住之后静态守卫会让重载**保留旧坞**、不装新的，与本条要求相反。
- 后果补充：坞在 `RunDock` 里的次序是先建窗、后接收录来源。资源管理器注册要写注册表并通知
  外壳，是最慢的一步，排在建窗之前会把重载期间那段无坞空白从约 0.3s 拉到约 1.8s（实测）。
  空白本身消不掉——它是「先拆后装」的固有代价。

## DEC-010 V4.4.0 注册方拥有候选、HV 普通唤起与快捷文件底座

- 状态：已接受
- 日期：2026-08-12
- 决策：
  1. 动态常用参数由命令注册方通过 `completion.values.<parameter>` 注解声明。Mercury 只解释已知 provider，不按其他模块命令名硬编码值；无声明时仅使用 `ParameterSpec.AllowedValues` 和参数结构。Mercury 自有项目命令统一声明 `mercury.projects`，控制台与管理页读取同一份补全定义。
  2. HV 扩展坞项与 `mercury.app.open` 执行普通 `vulcan.app.show`，`//` 仍只执行 `vulcan.app.focusconsole`。无总线回退仅激活真实前端窗口或启动正式名 `HistoryVulcan.exe`。
  3. 快捷文件统一收口到 `mercury.shortcut.open/add`。扩展坞持久化的是 `open` 命令；命令规范化只折叠引号外空白，必须保留引号内路径文本；未来拖放只把路径交给 `add`，不再建立第二套格式。
- 后果：Mercury 4.4.0 直接注册 24 条命令；`mercury.go` 用注解声明 `registry.domains`，远程 `vulcan.command.show` 必须保留注解；快捷文件路径是唯一位置参数，不生成 `path=`。

## DEC-012 V4.5.1 外壳通知按变化量收敛

- 状态：已接受
- 日期：2026-08-14
- 决策：三条。
  1. **`SHCNE_ASSOCCHANGED` 只用于命名空间项自身的增删改**。它是全局广播，会让每个外壳进程丢弃图标缓存
     并重读文件关联；目录内容变化改用 `SHCNE_UPDATEDIR` + `SHCNF_PATHW` 定点通知；没有变化则不发通知。
  2. **注册与快捷方式同步都必须幂等**。`RegisterOrUpdate` 逐项核对后一致即返回 `Changed=false` 且不写注册表；
     `Synchronize` 逐项比对受管字段，只重写不一致的 `.lnk`。两者都用返回值告知调用方是否真的动过。
  3. **快捷方式文件夹的写入方与解读方必须共享同一份状态**。`MercuryState.StartWatching` 提到 `Attach`
     阶段，服务进程与界面进程都跟随 `state.json`；增删到收录意图的翻译收口到纯函数
     `ResolveShortcutIntent`，同一轮的重写不产生意图，且任一项目名不得同时落入 `Pins` 与 `Excluded`。
- 原因：4.5.0 及之前每次 `RefreshAsync` 都无条件重写全部 `.lnk`、重写十余个注册表值并广播一次
  `ASSOCCHANGED`。实测单次广播约耗资源管理器主进程 20ms CPU，开启"在单独的进程中打开文件夹窗口"后每个
  窗口进程都要再付一次；日常一两百次刷新叠加长时间不重启外壳，表现为资源管理器越用越卡。同时服务进程不
  监视 `state.json`，两进程算出的收录列表可能不同，各自的写入被对方的监视器读成用户增删，反向篡改
  `Pins`/`Excluded` 并触发级联刷新——实测状态文件里出现过同一项目同时被固定与排除。
- 后果：命令集不变，仍为 26 条。`RegistrationResult` 增加 `Changed`，新增 `Unchanged` 工厂；
  `ShortcutSyncResult` 增加 `Unchanged` 与派生的 `Changed`；新增 `NotifyFolderChanged`；
  `MercuryState` 暴露内部纯函数 `ResolveShortcutIntent` 与 `SanitizePins` 供 Smoke 断言。
  `ShortcutFileService` 新增 `TryReadShortcut` 并在用完后立即释放 ShellLink 的 RCW。
  载入旧状态时会以排除优先清掉历史遗留的矛盾固定项，这是一次单向的数据修正。

## DEC-009 V4.2.0 域聚焦入口、无类直接方法与活动坞磁贴改色

- 状态：已接受
- 日期：2026-08-10
- 决策：分三条。
  1. **`mercury.go` 是域聚焦的唯一入口**，注册为本域的**无类直接方法**（两段名
     `mercury.go`，不声明 CommandClass）。`mercury.go <域>` 进入聚焦，
     `mercury.go` 无参退出。聚焦状态存放在共享的命令目录会话里，
     与 HistoryVulcan 控制台的域筛选下拉同源，两者自动同步。
  2. **命令名补全按域 → 类 → 方法 → 参数分段推进**。参数候选只取模块注册时提供的
     `ParameterSpec`，Mercury 不猜测参数名。域清单从传入的已注册命令定义现算，
     不硬编码。沿用既有的 Shift+W/S 选择与 Tab 确认。
  3. **活动坞磁贴改为白底圆角矩形 + 深黄文字，去掉光晕**。底色随使用频率由
     `#FFFFFF` 线性趋近 `#FAF0D8`，文字恒为 `#A87A12`；三个色值都取自
     HistoryVulcan UI 规范的 `Shell.Brush.Surface` / `AccentSoft` / `Accent` 浅色值。
- 原因：
  1. 退出聚焦若由各域自备指令，会让每个模块都耦合一条与自身业务无关的命令。
     宿主 DEC-025 的「首段命中已注册域即按绝对名解析」使 `mercury.go`
     在任何聚焦状态下都可直接输入，退出能力因此自然涌现，无需任何域配合。
     它切换的是控制台状态而非某类业务对象，所以不隶属任何类。
  2. 平铺全名候选在命令数上百后无法用键盘快速定位；分段推进让每一步的候选集
     都只有个位数到十几个。
  3. 光晕用模糊半径表达频率，在深色桌面上既不易分辨也会糊掉图标边缘；
     底色深浅是更直接的量度，且白底深黄文字在任意桌面壁纸上都可读。
- 后果：
  - 磁贴不再使用 `ProjectIconGenerator` 生成的缓存 PNG（底色需随频率实时变化，
    按名字哈希缓存的位图表达不了）；`ShortLabel` 提升为公开方法供磁贴取短标签。
    图标生成器本身保留，仍供资源管理器快捷方式使用。
  - `DockWeight.GlowOpacity` / `GlowBlur` / `MaxGlowOpacity` / `MaxGlowBlur`
    由 `TileTint` 取代。
  - Mercury 指令数 18 → 19，其中 1 条为无类直接方法。
- 替代条件：若 Mercury 的直接方法超过 5 条，应按 DEC-025 的替代条件评估是否建类。
