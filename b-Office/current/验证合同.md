# HistoryMercury Verification Contract

## Required Checks

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\b-Code\Test-ProjectContract.ps1 -Instantiation
dotnet build .\b-Code-MercuryDock\HistoryMercury.csproj -c Release -p:NuGetAudit=false
dotnet run --project .\b-Code-MercuryDock\tests\Smoke\Smoke.csproj -c Release -p:NuGetAudit=false
dotnet format .\b-Code-MercuryDock\HistoryMercury.csproj --verify-no-changes --no-restore
powershell -NoProfile -ExecutionPolicy Bypass -File .\b-Code\Publish-MercuryModules.ps1
```

The smoke gate verifies the module identity, direct 17-command catalog, lowercase `mercury` command names, absence of legacy command aliases, `HistoryMercury` runtime shortcut slot, UI registration owner, Explorer identity, layout behavior, and managed shortcut synchronization.

## Formal Promotion

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\b-Code\Publish-MercuryModules.ps1 -Publish
```

Promotion requires a clean committed source tree. It must create a hash-verified `z-HistoryMercury` containing only `HistoryMercury.dll`, `HistoryMercury.xml`, `module.manifest.json`, and `SHA256SUMS`; the old snapshot is retained under `b-Publish/history`.

## Runtime Check

After module reload, `module.list` must show `HistoryMercury 4.1.0`; `command.list` must contain only the 17 `mercury` commands above for this module; the Explorer entry must point to `%APPDATA%\HistoryVulcan\Modules\HistoryMercury\快捷方式`; double-slash global shortcut must wake `vulcan.frontend.focusconsole`; and the command workbench (catalog/detail) must attach via Mercury UI.
