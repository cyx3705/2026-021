REQ-MERC-463 adds a source-layout gate: production code remains under the responsibility folders in
`b-Code-MercuryDock`; Smoke lives in `b-Code-Tests/HistoryMercury.Smoke`; version documents live directly in
`b-Office/history`. Active manifests and Diana's release validation must not reference the retired nested
`b-Code-MercuryDock/tests` or `b-Code-MercuryDock/docs` paths.

4.5.1 adds shell-convergence regressions to the smoke gate: an unchanged shortcut folder must report `Written=0` / `Removed=0` / `Unchanged=1` and `Changed=false`, a changed managed field must still rewrite in place, and `ResolveShortcutIntent` / `SanitizePins` must never place one project in both `Pins` and `Excluded`. Registration idempotence is verified against the live per-user registration (`Changed=false`, no registry write, no shell notification).

The smoke gate verifies the module identity, direct 31-command catalog, lowercase `mercury` command names, absence of legacy aliases, the mutable `HistoryMercury` shortcut data root outside `Modules`, Explorer identity (`HistoryClio 项目`), HistoryClio library-root coercion and malformed-setting type fallback, managed shortcut synchronization, registration-owned `registry.domains` / `mercury.projects` / `mercury.dock.commands` annotations, quote-aware dock-command normalization, shortcut file resolution/registration, strict HV executable fallback, dock-entry add/remove handlers, and the real `MercuryShortcutModule` owner lifecycle.

5.0.0 replaces the 4.7.0 BAML gates with stronger ones, because there is no BAML left to inspect: the module must ship
**no** compiled XAML at all (`HistoryMercury.g.resources` must not exist), exactly one public `IModuleContextAware`
entry type which must also be `IDisposable`, and no type may implement any of the host UI lifecycle contracts deleted in
HistoryVulcan 5.0. Constructing the module must not put the dock on the desktop, and `Dispose` must be re-entrant.

5.0.0 also gates the text protocol, which has no compiler behind it: `mercury.ui.describe` and `mercury.ui.actions`
must parse as JSON and satisfy Aurora's own checks (schemaVersion, owner, lowercase unique page ids, every page-level
action id declared, every declared `mercury.*` command actually registered), the `entries` view must carry exactly the
columns the description declares, the three `mercury.ui.*` commands and `mercury.dock.run` must declare a
`HiddenReason`, and `mercury.dock.run` must reject both a key that is not in the dock and raw command text.

5.0.1 adds three gates to the description, one per tightened Aurora rule. All three failure modes are silent —
the page keeps rendering and the buttons keep looking like buttons:

- **No retired page node types.** `button` / `input` / `select` stopped being page nodes in Aurora 1.8.14;
  5.0.0 shipped seven `type: "button"` nodes and every one of them renders as a retirement notice on 1.9.x.
- **No `view` on tables.** `filterable` / `sortable` / `selection` parse but have no implementation anywhere in
  Aurora (its REQ-UI-054 books this as a debt). Declaring them promises filtering that will never happen.
- **Row-action placeholders must be columns the entries view actually produces.** A mismatch does not fail —
  it sends an empty value onto the bus, so the symptom is "clicked it, nothing happened", with no log on either
  side. This one can only be checked after the data view has produced a row, so it lives in the data block.

Also gated by the manual pass, not by smoke: the dock's pinned marker is now a ring on the tile rather than a
`·` after the number, and the tile keeps a 2px border in both states so the glyph font size does not change when
a project is pinned.

## Runtime Check

`vulcan.command.list` must contain all 31 `mercury` commands, including `mercury.go`, the three `mercury.ui.*`, `mercury.dock.add/remove`, `mercury.shortcut.open/add`, and compatibility `mercury.shortcut.wakeconsole`. `aurora.ui.reloadpages` must report two Mercury pages built and `aurora.ui.missing` must list no Mercury component; every button on the manager page must act (an unbound action renders as an explicit placeholder, which is the failure this protocol exists to make visible). Source acceptance is `HistoryMercury 5.0.0` on host `HistoryVulcan 5.1.0`; the Explorer entry must read `HistoryClio 项目`, the dock tile `HC`, and the project scan must use HistoryClio. After installation, `vulcan.module.reload` and a full host restart must both keep HistoryMercury loaded; no mutable file may appear below its runtime package slot. 4.7.0 adds two dock checks. Independence: with the frontend hidden or never opened, the desktop dock must still be on screen, and its `HC` tile must bring the frontend up; the manager page is a frontend page and is expected to be absent while the frontend is closed. Reload: across a `vulcan.module.reload` the host process must never hold more than one dock window, and must hold exactly one once the reload completes, with `[dock] 桌面坞已就绪` in the log. The host tears the old package down before it builds the new one, so a brief no-dock window (~0.3s measured) is expected and is not a defect. This is runtime-only; a headless smoke cannot create windows and therefore cannot cover it.
