## Command Contract

Commands are registered once through `IModuleContext.RegisterCommands`; `ModuleInfo.MainClassType` is intentionally `null` so the host never creates a second reflection-derived command surface. All public command names are lowercase and match `^[a-z]+(\.[a-z0-9]+)+$`.

| Command group | Commands |
| --- | --- |
| direct | `mercury.go` |
| application | `mercury.app.status`, `.open` |
| shortcut | `mercury.shortcut.wakeconsole`, `.open`, `.add` |
| project | `mercury.proj.list`, `.open`, `.add`, `.pin`, `.unpin`, `.refresh`, `.exclude`, `.include` |

`mercury.app.status`, `mercury.proj.list`, and `mercury.usage.list` are read-only. Removing the Explorer entry or clearing usage history requires host confirmation. `dock.*` and `mercury.dock.open` are removed, not aliased.

## REQ-MERC-451 外壳通知与快捷方式文件夹的所有权

刷新是高频动作，而快捷方式文件夹是钉在"此电脑"下的命名空间扩展，因此写入与通知都必须按变化量收敛。

- **注册幂等**：`RegisterOrUpdate` 先逐项核对本模块写入的每一个注册值（显示名、固定标记、排序号、
  托管标记、`DefaultIcon`、`InProcServer32` + `ThreadingModel`、`Instance\CLSID`、`TargetFolderPath`、
  `ShellFolder\Attributes`、`MyComputer\NameSpace` 显示名），全部相符时既不写注册表也不发通知，
  返回 `Changed=false`。任一项缺失或不符仍会整体重写，半写坏的注册因此能自愈。
  `ExpandString` 必须按未展开的原始值比较；GUID 与路径按大小写无关比较。
- **通知分级**：`SHCNE_ASSOCCHANGED` 只在注册项本身增删改时发送，因为它会让每个外壳进程丢弃图标缓存并
  重读文件关联，在"在单独的进程中打开文件夹窗口"开启时代价按窗口进程数翻倍。目录内容变化改用
  `NotifyFolderChanged`（`SHCNE_UPDATEDIR` + `SHCNF_PATHW`）定点通知。两者都没变则一个通知都不发。
- **快捷方式按差异写**：`Synchronize` 逐项比对目标路径、描述、图标源与图标序号，只重写不一致的 `.lnk`，
  并报告 `Written` / `Removed` / `Unchanged` 与派生的 `Changed`。写入期间挂起自己的 `FileSystemWatcher`，
  写完以现状为新基线再恢复。
- **收录意图判定**：`MercuryState.ResolveShortcutIntent` 是纯函数。同一轮里既消失又出现的项目视为一次重写、
  不产生意图；已排除的项目不再重复排除；已固定且未排除的项目不再重复固定。任一项目名不会同时进入
  `Pins` 和 `Excluded`；载入旧状态时 `SanitizePins` 以排除优先清理历史矛盾。
- **跨进程一致**：`MercuryState.StartWatching` 在 `Attach` 阶段执行，服务进程与界面进程都跟随 `state.json`。
  两侧偏好副本一致是"不把对方的写入读成用户增删"的前提。

## REQ-MERC-452 宿主引用面与建界面的失败隔离

- **编译目标就是运行目标**：`HistoryMercury.csproj` 默认引用 `z-Publish/host` 下已发布的宿主程序集，
  与 `project.manifest.json` 的 `externalDependencies` 一致。对宿主源码树联调必须显式传
  `-p:HistoryVulcanSourceAvailable=true`。`AssertHistoryVulcanReference` 目标在两条路径上各自校验前提：
  显式选源码时源码工程必须存在，默认路径下已发布快照必须存在。
- **桌面坞不作为宿主内扩展的下游**：管理页与命令工作台各自捕获异常并只记告警，任何一处失败
  都不得带走另一处。4.7.0 起桌面坞已整体移出这条链，见 REQ-MERC-470。

## REQ-MERC-470 桌面坞的界面自持

桌面坞是唤起前端的入口，因此它不能依赖前端。依赖不是靠调用顺序回避，而是结构上不存在。

- **起点**：桌面坞在 `Attach` 阶段启动，跑在本模块自建的 STA 线程与 Dispatcher 上。
  只要模块装载，坞就存在；前端装没装、开没开、重载没重载都与它无关。
- **判据**：能不能建坞只取决于本模块能不能开出一条 STA 线程。不得再以
  `Application.Current` 是否为 null 判断「此进程有没有界面」——DEC-008 之后前端在宿主进程内
  开窗时刻意不建 WPF Application，那个判据恒真。
- **归属**：快捷方式文件夹监视与资源管理器命名空间注册属于坞，随坞一起在 `Attach` 阶段启动。
  `CreateUi` 只保留管理页与命令工作台两处前端内扩展。
- **收尾**：`DestroyUi` 必须关窗、停 Dispatcher 并回收线程（join 上限 5s）。模块运行在可回收的
  装载上下文里，线程不收就会在卸载后继续跑已卸载的类型。
- **视觉自持**：`DockTheme` 的颜色、字体与间距全部由本模块持有，取值与前端令牌一致但不查前端。
  坞在前端起来之前就要显示。
- **前端内视图**：管理页与两处工作台视图一律用 `DynamicResource` 取宿主界面的资源，不在本地合并
  Aurora 的样式字典。本地合并只覆盖被合并那一份字典里的键，漏掉的键在解析 `StaticResource` 时
  抛 `StaticResourceExtension` 并把整页带走。
- **重载**：宿主热重载是「先拆旧、再装新」（`ModuleHost.Reload.cs`），新旧两坞不会并存。
  `Attach` 必须等到坞的就绪信号才返回（上限 10s，超时只告警）：否则下一轮拆除可能撞上
  还没建完的窗口，`StopDesktopDock` 扑空，随后建出的窗口没人持有引用，成为关不掉的孤坞。
  `RunDock` 内先建窗、后接收录来源——资源管理器注册要写注册表并通知外壳，排在建窗之前
  会把重载期间的无坞空白从约 0.3s 拉到约 1.8s。空白本身是「先拆后装」的固有代价，消不掉。
  不得改用 `pinned: true` 回避——钉住会让重载保留旧坞、不装新的。
- **验收**：Smoke 断言 `CreateUi` 之后桌面坞未在运行（坞不在前端那条链上）、模块 BAML 中不含
  `HistoryAurora` 的 pack URI、管理页能在无前端的 STA 线程上完整构造。重载交接不在 Smoke 覆盖内
  （无头环境不建窗），由运行验收承担：`vulcan.module.reload` 全程桌面上的坞数不得超过 1，
  完成后必须恰好为 1，且日志有 `[dock] 桌面坞已就绪`。
  运行验收还要求前端关闭状态下坞仍在桌面上，且点击坞上的 `HC` 磁贴能把前端唤起。

## Completion And Focus

Completion advances domain -> class -> method -> parameter after a dot or Tab confirmation. Candidates use case-insensitive exact, prefix, then contains ranking. Parameters declaring `Position=0` use the bare `method value` form; named-only parameters retain `name=`. Free-text positional parameters expose only the parameter shape and never invent value candidates. Mercury's `//` shortcut dispatches the Vulcan-owned `vulcan.app.focusconsole` semantic command; `mercury.shortcut.wakeconsole` remains as a compatibility command.

When a domain is focused, a short class token is resolved exactly once against that domain. For example, `proj.` under focus `janus` completes from `janus.proj.*`; the engine must not construct a duplicated prefix such as `janus.janus.proj.*`. Method completion then exposes only registered `ParameterSpec` metadata and allowed or dynamic values.

`CommandCatalogSession` resolves a short command against the focused domain before calling `vulcan.command.show`; under Mercury focus, `go ` therefore queries `mercury.go`, never `go`. `CommandCatalogDetail.Annotations` and locally registered annotations are merged. A dynamic value provider is used only when the command registrant declares `completion.values.<parameter>`; `registry.domains` is the provider declared by `mercury.go`, and Mercury project commands declare the Mercury-owned `mercury.projects` provider. The console and manager entry field consume the same completion definitions. Mercury does not infer another module's common values from command names.

## REQ-MERC-440 Frontend And Shortcut Entries

- The HC tile and `mercury.app.open` first execute `vulcan.app.show`. If the bus cannot show the frontend, fallback activation accepts only a `HistoryVulcan` process with a real main window, and cold start resolves only `HistoryVulcan.exe`.
- `mercury.shortcut.open` and `mercury.shortcut.add` each declare one required `path` parameter at `Position=0`. `.lnk` files are resolved before opening; direct files and directories are also accepted. Missing sources, unresolved links, and missing targets return explicit failures.
- `mercury.shortcut.add` persists the normalized source path through `mercury.shortcut.open`, derives a stable filename label, quotes command text with `CommandParser`, and deduplicates by normalized command text. Future dock drag-and-drop must call this same registration path.
- Dock command normalization collapses whitespace only outside quoted arguments. Quotes, escape runs, and whitespace inside a quoted path are preserved byte-for-byte so paths such as `"C:\A  B.lnk"` remain executable.
- Acceptance is the 26-command Smoke catalog plus direct-file, `.lnk`, failure, label, quoting, deduplication, focused `go `, HV executable-resolution, dock-entry add/remove, manager-page Shell-resource regressions, the `HC` tile contract, the `HistoryClio 项目` Explorer identity, and library-root coercion from HistoryVesta to HistoryClio.

## REQ-MERC-460 HistoryClio 可见品牌与项目库根

- **坞磁贴**：桌面坞固定入口的标识是 `HC`（HistoryClio），工具提示为「打开 HistoryClio 主界面」。点击仍执行 `vulcan.app.show` / `HistoryVulcan.exe` 冷启动，宿主进程名不变。
- **资源管理器入口**：每用户命名空间项显示名为 `HistoryClio 项目`。CLSID 不变；下次 `RegisterOrUpdate` 因显示名不一致而重写注册表并发送 `SHCNE_ASSOCCHANGED`。
- **扫描根**：`MercuryState` 优先读 `proj.libraryroot`，其次现存的 `proj.worktreeroot`，缺省 `C:\OneHistory\HistoryClio`。路径等于 `C:\OneHistory\HistoryVesta` 或目录内含 `HistoryVesta.git` 时改写到 Clio。

## REQ-MERC-461 设置值类型容错

- `proj.libraryroot` 与 `proj.worktreeroot` 只有 JSON 字符串值才参与路径解析；数字、布尔、null、对象和空白字符串按缺失处理。
- 无有效路径时继续回退到 `C:\OneHistory\HistoryClio`，不能因手工编辑或旧配置残留让活动坞扫描抛出异常。
