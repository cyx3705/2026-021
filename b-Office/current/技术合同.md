# HistoryMercury Technical Contract

## Identity

- Project: `2026-021-HistoryMercury`.
- Module identity: `HistoryMercury`.
- Code namespace and command domain: `Mercury` / `mercury`.
- Formal consumer snapshot: `z-Publish`.
- Artifact pair: `HistoryMercury.dll` and `HistoryMercury.xml`.
- Current source version: `5.0.3`.
- Minimum host: HistoryVulcan **5.1.0** (`z-Publish/host`); frontend: HistoryAurora page-registration protocol **V1**,
  panel protocol **V3** (HistoryAurora ≥ 1.9.2, hard).

## Command Contract

Commands are registered once through `IModuleContext.RegisterCommands`; `ModuleInfo.MainClassType` is intentionally `null` so the host never creates a second reflection-derived command surface. All public command names are lowercase and match `^[a-z]+(\.[a-z0-9]+)+$`.

| Command group | Commands |
| --- | --- |
| direct | `mercury.go` |
| application | `mercury.app.status`, `.open` |
| shortcut | `mercury.shortcut.wakeconsole`, `.open`, `.add`, `.pick` |
| project | `mercury.proj.list`, `.open`, `.add`, `.pin`, `.unpin`, `.refresh`, `.exclude`, `.include` |
| Explorer | `mercury.explorer.register`, `.remove` |
| dock | `mercury.dock.hide`, `.show`, `.policy` |
| dock entries | `mercury.dock.add`, `.remove`, `.run` |
| usage | `mercury.usage.list`, `.forget` |
| hotkey | `mercury.hotkey.list`, `.register`, `.unregister` |
| page protocol | `mercury.ui.describe`, `.actions`, `.data` |

`mercury.app.status`, `mercury.proj.list`, `mercury.usage.list` and the three `mercury.ui.*` commands are read-only. Removing the Explorer entry or clearing usage history requires host confirmation. `dock.*` and `mercury.dock.open` are removed, not aliased.

The three `mercury.ui.*` commands and `mercury.dock.run` each declare a `HiddenReason`. From HistoryVulcan 5.0 the host no longer projects MCP exposure for modules — `HiddenReason` is the only thing a remote surface reads — so an in-frontend protocol that stays silent about it becomes remotely callable.

## Runtime Data And Migration

- Current state, icon cache, and Explorer backup: `%APPDATA%\HistoryVulcan\HistoryMercury`.
- Current managed shortcut folder: `%APPDATA%\HistoryVulcan\HistoryMercury\快捷方式`.
- `%APPDATA%\HistoryVulcan\Modules\HistoryMercury` is the immutable, manifest-verified runtime package slot;
  Mercury must not create state, caches, shortcuts, logs, or other mutable files below it.
- On first use, state migration reads but never deletes, in order: `%APPDATA%\HistoryVulcan\MercuryDock`, `%APPDATA%\OneHistoryStudio\MercuryDock`, and `%APPDATA%\OneHistoryStudio\ActiveDock`.
- Explorer ownership is now `HistoryMercury.Managed`; old `MercuryDock.Managed` and `ActiveDock.Managed` are read-only migration identifiers.

## REQ-MERC-451 外壳通知与快捷方式文件夹的所有权

刷新是高频动作，而快捷方式文件夹是钉在"此电脑"下的命名空间扩展，因此写入与通知都必须按变化量收敛。

- **注册幂等**：`RegisterOrUpdate` 先逐项核对本模块写入的每一个注册值（显示名、固定标记、排序号、
  托管标记、`DefaultIcon`、`InProcServer32` + `ThreadingModel`、`Instance\CLSID`、`TargetFolderPath`、
  `ShellFolder\Attributes`、`MyComputer\NameSpace` 显示名），全部相符时既不写注册表也不发通知，
  返回 `Changed=false`。任一项缺失或不符仍会整体重写，半写坏的注册因此能自愈。
  `ExpandString` 必须按未展开的原始值比较；GUID 与路径按大小写无关比较。
- **通知分级**：`SHCNE_ASSOCCHANGED` 只在注册项本身增删改时发送，因为它会让每个外壳进程丢弃图标缓存并
  重读文件关联，在"在单独的进程中打开文件夹窗口"开启时代价按窗口进程数翻倍。目录内容变化改用
  `NotifyFolderChanged`（`SHCNE_UPDATEDIR` + `SHCNF_PATHW`）定点通知。两者都没变则一个通知都不发。
- **快捷方式按差异写**：`Synchronize` 逐项比对目标路径、描述、图标源与图标序号，只重写不一致的 `.lnk`，
  并报告 `Written` / `Removed` / `Unchanged` 与派生的 `Changed`。写入期间挂起自己的 `FileSystemWatcher`，
  写完以现状为新基线再恢复。
- **收录意图判定**：`MercuryState.ResolveShortcutIntent` 是纯函数。同一轮里既消失又出现的项目视为一次重写、
  不产生意图；已排除的项目不再重复排除；已固定且未排除的项目不再重复固定。任一项目名不会同时进入
  `Pins` 和 `Excluded`；载入旧状态时 `SanitizePins` 以排除优先清理历史矛盾。
- **跨进程一致**：`MercuryState.StartWatching` 在 `Attach` 阶段执行，服务进程与界面进程都跟随 `state.json`。
  两侧偏好副本一致是"不把对方的写入读成用户增删"的前提。

## REQ-MERC-452 宿主引用面与建界面的失败隔离

- **编译目标就是运行目标**：`HistoryMercury.csproj` 默认引用 `z-Publish/host` 下已发布的宿主程序集，
  与 `project.manifest.json` 的 `externalDependencies` 一致。对宿主源码树联调必须显式传
  `-p:HistoryVulcanSourceAvailable=true`。`AssertHistoryVulcanReference` 目标在两条路径上各自校验前提：
  显式选源码时源码工程必须存在，默认路径下已发布快照必须存在。
- **桌面坞不作为宿主内扩展的下游**：4.7.0 起桌面坞已整体移出这条链，见 REQ-MERC-470。
  5.0 之后这条链本身也不存在了：宿主不再编排模块界面，页面是数据（REQ-MERC-500），
  一页描述解析失败只影响那一页，由 Aurora 逐页隔离。

## REQ-MERC-470 桌面坞的界面自持

桌面坞是唤起前端的入口，因此它不能依赖前端。依赖不是靠调用顺序回避，而是结构上不存在。

- **起点**：桌面坞在 `Attach` 阶段启动，跑在本模块自建的 STA 线程与 Dispatcher 上。
  只要模块装载，坞就存在；前端装没装、开没开、重载没重载都与它无关。
- **判据**：能不能建坞只取决于本模块能不能开出一条 STA 线程。不得再以
  `Application.Current` 是否为 null 判断「此进程有没有界面」——DEC-008 之后前端在宿主进程内
  开窗时刻意不建 WPF Application，那个判据恒真。
- **归属**：快捷方式文件夹监视与资源管理器命名空间注册属于坞，随坞一起在 `Attach` 阶段启动。
- **收尾**：`Dispose` 必须关窗、停 Dispatcher 并回收线程（join 上限 5s），并停掉状态监视与
  快捷键钩子。模块运行在可回收的装载上下文里，线程不收就会在卸载后继续跑已卸载的类型。
  5.0 之前这段在 `DestroyUi` 里，而宿主只在有前端时才调它。
- **视觉自持**：`DockTheme` 的颜色、字体与间距全部由本模块持有，取值与前端令牌一致但不查前端。
  坞在前端起来之前就要显示。
- **前端内视图**：5.0 起模块不再有前端内视图。样式键、`DynamicResource` 与本地合并样式字典的
  那类失败形态随之消失——描述里根本不接受样式键（REQ-MERC-500 / DEC-018）。
- **重载**：宿主热重载是「先拆旧、再装新」（`ModuleHost.Reload.cs`），新旧两坞不会并存。
  `Attach` 必须等到坞的就绪信号才返回（上限 10s，超时只告警）：否则下一轮拆除可能撞上
  还没建完的窗口，`StopDesktopDock` 扑空，随后建出的窗口没人持有引用，成为关不掉的孤坞。
  `RunDock` 内先建窗、后接收录来源——资源管理器注册要写注册表并通知外壳，排在建窗之前
  会把重载期间的无坞空白从约 0.3s 拉到约 1.8s。空白本身是「先拆后装」的固有代价，消不掉。
  不得改用 `pinned: true` 回避——钉住会让重载保留旧坞、不装新的。
- **验收**：Smoke 断言构造模块实例不会把坞带上桌面、`Dispose` 可重入且不留坞、模块里没有编译后的
  XAML。重载交接不在 Smoke 覆盖内
  （无头环境不建窗），由运行验收承担：`vulcan.module.reload` 全程桌面上的坞数不得超过 1，
  完成后必须恰好为 1，且日志有 `[dock] 桌面坞已就绪`。
  运行验收还要求前端关闭状态下坞仍在桌面上，且点击坞上的 `HC` 磁贴能把前端唤起。

## REQ-MERC-500 描述化前端与宿主 5.1 的模块面

宿主 5.0 拆掉了模块的界面 SDK，前端同轮改为描述化。本节是 Mercury 在新形状下的对外面。

- **模块入口**：`MercuryModule` 实现 `IModuleContextAware` + `IDisposable`，没有别的生命周期方法。
  `Attach` 挂总线、登记指令、起状态监视、起快捷键服务与桌面坞；`Dispose` 逆序收回。
  宿主按 `IDisposable` 在卸载可回收上下文之前回收实例，因此**线程与钩子必须在 `Dispose` 里收干净**。
- **页面是数据**：`mercury.ui.describe` 返回页面描述（schemaVersion=1、owner=`HistoryMercury`），
  `mercury.ui.actions` 返回动作声明，`mercury.ui.data view=` 返回行数据。
  三条都返回同一份 JSON 在 `Data` 与 `Message` 两处——`Data` 是 `object?`，跨进程中继后
  结构化载荷不保证存活，只放 `Data` 会得到「进程内能用、跨进程静默空表」。
- **模块不构造任何前端控件**：本仓不再有 XAML 页面，编译产物里不得出现 `HistoryMercury.g.resources`。
  桌面坞是例外之外的东西——它不是前端里的页，是模块自己的窗口，代码构造，见 REQ-MERC-470。
- **按钮绑动作 id，不绑指令名**：动作 id 以 `mercury.entry.` 起头。指令改名只改
  `MercuryPages.ActionsJson` 里的 `command` 一处；页面描述与按钮不动。
  声明里指向 `mercury.*` 的每一条指令都必须真的注册着（烟测逐条比对）。
- **页面清单**（5.0.2 精简，见 REQ-MERC-501 / REQ-MERC-502）：
  - `dock.manager`（中央、默认可见）：一条横排工具条（刷新 + 收录策略）、
    条目表格（六列数据，`rowActions` 一律 `inline: false`），以及一个
    `trigger: "context"` 的加入弹出层。页面上没有说明文字，也没有任何按钮列：
    右键空白处加入条目，右键某一行取该行的全部操作。
  - 只有这一页。5.0.0–5.0.2 另声明过 `mercury.commands`（命令集），与 Aurora 自带的命令集页重复，
    5.0.3 删去（DEC-021）；`mercury.ui.data` 随之只剩 `entries` 一个视图。
- **`mercury.dock.run`**：页面「打开」按钮的落点。只接受 `proj:<项目名>` / `cmd:<指令文本>`
  两种行键，且必须在当前坞状态里查得到；否则它就是一条「代为执行任意指令」的旁路，
  远端逐条排除会被它整个绕开。
- **文件选择**：`mercury.shortcut.pick` 把「开对话框」与「加入」收成一条指令。
  协议里没有「把一条指令的结果写回某个控件」的表达，拆成两步就会得到一个点了没反应的按钮；
  选择归前端（`aurora.ui.selectfile`），加入归本模块。取消返回成功，不是失败。
- **上行通知**：坞状态一变，`PageInvalidation` 合并 300ms 后发一条
  `aurora.ui.invalidate owner=HistoryMercury`。页面是派生状态（表格建页时取一次数、
  策略面板的初值写在描述里），不发这条就永远停在建页那一刻。前端不在时该指令不存在，
  总线立刻失败，按「现在没有界面要更新」静默处理，不刷告警。
- **域聚焦**：`mercury.go` 转发 `aurora.log.source`。未装前端时该指令不存在，总线立刻明确失败。
- **模块日志**：`Mercury.Diagnostics.MercuryLog` 实现 `IShellLog`，内存环形缓冲 512 条 +
  落盘到 `%APPDATA%\HistoryVulcan\HistoryMercury\logs\mercury-<日期>.log`。
  落盘失败一律吞掉：记不下日志是小事，为记日志把坞或模块装载带崩不是。
- **验收**：Smoke 断言入口类型恰好一个且实现 `IDisposable`、没有任何类型实现已删除的宿主界面契约、
  程序集里没有编译后的 XAML、描述与声明是合法 JSON 且满足 Aurora 的校验口径
  （版本、owner、页面 id 小写无空格且不重复、页面引用的动作全部已声明）、
  取数列与描述列对齐、`mercury.dock.run` 拒绝不在坞里的行键与裸指令文本。

## REQ-MERC-501 页面跟上 Aurora 1.8.14 → 1.9.1 的三条收紧（5.0.1）

5.0.0 的描述是对着 Aurora 1.7 写的。前端此后走到 1.9.1，三条变更让这一页**看起来还在、
点下去没反应**——三种失败形态都不报错，因此必须逐条钉在门禁里。

- **行操作改走 `rowActions`。** Aurora 1.8.14 起 `button` / `input` / `select` 不再是
  页面节点，页面按钮的 `invoke` / `enabledWhen` 一并退役。5.0.0 在表格下面排了 7 个
  `type: "button"`，1.9.x 上**整排渲染成写着退役原因的牌子**：扩展坞管理页的
  打开 / 固定 / 排除 / 移除全部失效，而模块侧一条错误都没有。
  现在一份 `rowActions` 声明同时给出行内按钮与右键菜单，占位符按**被点那一行的同名列**取值，
  不再绕 `entries.selected.name` 那种跨节点路径，也不再有「选中」这个中间态。
  行内只留「打开」「固定」；取消固定 / 排除 / 重新纳入 / 移除常驻项写 `inline: false`
  只进右键菜单——六个按钮会把数据列挤没，而那正是这个组件要解决的问题的反面。
- **不再声明 `view`。** `filterable` / `sortable` / `selection` 在 Aurora 里解析得了、
  全仓没人读（Aurora REQ-UI-054 已记账）。留着只会让人以为这张表能筛能排。
- **版面改横排，加入面板移出版面。** Aurora 1.9.0 起页面不滚、装不下就裁掉
  （REQ-UI-050），于是顶上每多一行，条目表就少一行。收录策略与刷新收成一条横排工具条
  （一个 `even` 声明行；随 Aurora 1.9.2 的协议 V3 从 `orientation: "horizontal"` 改来，
  三个数字框写 `minWidth: 64`，并去掉了已退役的 `required`）；「加入扩展坞」整块改成
  `trigger: "context"` 的弹出层，右键页面空白处唤起。它是这一页最高的一块，
  使用频率却是一周一两次。
- **右键这条能力是本页提出、由 Aurora 交付的**（Aurora 1.9.1 / REQ-UI-056）。
  弹出层本来就存在，缺的只是一个不占版面的触发方式，因此 Aurora 那边**没有新建组件**，
  只给现成的浮层多了一条开关——这正是 DEC-005「不自建组件、但必须有出口」的走法。
  代价是看不见：版面上没有东西提示「这里右键有内容」，所以页首那句说明必须写出来。
- **依赖**：本页需要 HistoryAurora ≥ **1.9.2**，而且是**硬**依赖——1.9.2 的面板协议 V3
  把 `widgets` 换成了 `rows`，更早的 Aurora 拿到只写 `rows` 的声明会画出一块空面板。
  1.9.1 那条下限（`popup.trigger`）备查：装在 1.9.0 上时 `trigger` 被解析器忽略，
  加入弹出层退回自带按钮的形态——那一条是「功能不丢，只是多占一行」，与这次不同。
- **验收**：Smoke 新增三条门禁——描述里不得出现退役的页面节点类型（`button` / `input` /
  `select`）、表格不得声明 `view`、行操作的每个占位符都必须是取数产出的列名。
  第三条只能在取数真的产出一行之后查：对不上不会报错，只会把一个空值发上总线。

## REQ-MERC-502 面板协议 V3 落地与管理页精简（5.0.2）

本节两件事：把 5.0.1 已经写好但没发布的面板改动发出去，以及按版面预算再砍一轮。

- **V3 是运行期硬下限，提交不等于生效。** Aurora 1.9.2（REQ-UI-060）把面板的 `widgets`
  换成 `rows`，不留兼容分支。本仓在 5.0.1 之后已按 V3 重写两个面板，但那次改动**只提交、
  没发布**：运行中的 5.0.1 运行包仍是平铺 `widgets`，Aurora 拿到只有 `widgets` 的声明后
  `rows` 为空，`PanelDefinitionValidator` 判它合法（零行也是合法的），于是顶上那条工具条
  与右键「加入扩展坞」浮层**都画成一块空面板**——不报错、不缺件、日志里一个字都没有。
  验收因此不能停在「源码已改」：模块的对外面是**已安装的运行包**，`z` 与 AppData 里的版本
  才是生效的那一份。
- **页首说明去掉。** 页面不滚（Aurora REQ-UI-050），这一行的成本是条目表少一行。
  它换来的是「右键有内容」这条提示，而这条提示只在第一次有用。
- **「最近打开」列下表。** 取数照常产出这一列——行操作占位符按被点那一行的同名列取值，
  烟测也仍在比对取数列——只是不再上表。**下表不等于不取**，两者必须分开说。
- **行操作一律 `inline: false`，「操作」列因此整列消失。** Aurora 只在存在 inline 行操作时
  才在最右建那一列（`AuroraTable`），而右键菜单收的一直是全部动作。行内按钮列是两个出口里
  更贵的那个：它按最长的一组按钮占宽，占的是每一行的宽度。
- **代价写在这里，不写在页面上**：这一页现在没有任何东西提示右键有内容。加入条目在页面右键、
  行操作在行右键，两处都看不见。这是 DEC-020 明确取的舍，不是把提示漏掉了。
- **验收**：Smoke 新增三条门禁——管理页不得出现 `text` 节点、表格不得声明 `lastopened` 列、
  任何一条行操作都不得声明或默认 `inline: true`（`inline` 缺省值在 Aurora 那一侧，
  因此"不写"也算违规）。三条都只查描述，与取数产出的列无关。

## Boundaries

`b-Code-MercuryDock/module.manifest.json` is the manifest authority. `b-Code/Build-HistoryMercuryPackage.ps1` creates a verified candidate;
formal promotion to `z-Publish` and the Diana consumer-document mirror is owned by the centralized Diana publisher.
The module consumes the published `HistoryVulcan.Core` and `HistoryVulcan.Services` contracts and does not copy host assemblies. `HistoryVulcan.Extensibility` was deleted by the host in 5.0 and is no longer referenced.

Project-contract validation moved into the host's in-process development pipeline
(`HistoryVulcan.Services.Development.Pipeline.ProjectContract`); the shared Diana script this repo used to forward to
no longer exists, so `commands.verify` is `null` and `b-Code/Test-ProjectContract.ps1` was removed rather than left
pointing at a missing file.

## Completion And Focus

Console completion, the command set and the detail view belong to HistoryAurora from host 5.0: the
`IShellCommandWorkbenchHost` mount point Mercury used to attach its catalog session to was deleted, and so were the
session/completion contracts it implemented. Mercury keeps only the entry point that has bus semantics: `mercury.go`
relays `aurora.log.source`, which is the single writer of the console domain filter that `ConsoleView` feeds to
`DomainFocus.Resolve`. Registration metadata that used to drive completion (`completion.values.<parameter>` with the
`registry.domains` / `mercury.projects` / `mercury.dock.commands` providers) stays on the descriptors — it is
consumed by whoever implements completion, and the annotations are the durable half of that contract.

## REQ-MERC-440 Frontend And Shortcut Entries

- The HC tile and `mercury.app.open` first execute `vulcan.app.show`. If the bus cannot show the frontend, fallback activation accepts only a `HistoryVulcan` process with a real main window, and cold start resolves only `HistoryVulcan.exe`.
- `mercury.shortcut.open` and `mercury.shortcut.add` each declare one required `path` parameter at `Position=0`. `.lnk` files are resolved before opening; direct files and directories are also accepted. Missing sources, unresolved links, and missing targets return explicit failures.
- `mercury.shortcut.add` persists the normalized source path through `mercury.shortcut.open`, derives a stable filename label, quotes command text with `CommandParser`, and deduplicates by normalized command text. Future dock drag-and-drop must call this same registration path.
- Dock command normalization collapses whitespace only outside quoted arguments. Quotes, escape runs, and whitespace inside a quoted path are preserved byte-for-byte so paths such as `"C:\A  B.lnk"` remain executable.
- Acceptance is the 31-command Smoke catalog plus direct-file, `.lnk`, failure, label, quoting, deduplication, focused `go `, HV executable-resolution, dock-entry add/remove, page-description regressions, the `HC` tile contract, the `HistoryClio 项目` Explorer identity, and library-root coercion from HistoryVesta to HistoryClio.
