## Completion And Focus

Completion advances domain -> class -> method -> parameter after a dot or Tab confirmation. Candidates use case-insensitive exact, prefix, then contains ranking. Parameters declaring `Position=0` use the bare `method value` form; named-only parameters retain `name=`. Free-text positional parameters expose only the parameter shape and never invent value candidates. Mercury's `//` shortcut dispatches the Vulcan-owned `vulcan.app.focusconsole` semantic command; `mercury.shortcut.wakeconsole` remains as a compatibility command.

When a domain is focused, a short class token is resolved exactly once against that domain. For example, `proj.` under focus `janus` completes from `janus.proj.*`; the engine must not construct a duplicated prefix such as `janus.janus.proj.*`. Method completion then exposes only registered `ParameterSpec` metadata and allowed or dynamic values.

`CommandCatalogSession` resolves a short command against the focused domain before calling `vulcan.command.show`; under Mercury focus, `go ` therefore queries `mercury.go`, never `go`. `CommandCatalogDetail.Annotations` and locally registered annotations are merged. A dynamic value provider is used only when the command registrant declares `completion.values.<parameter>`; `registry.domains` is the provider declared by `mercury.go`, and Mercury project commands declare the Mercury-owned `mercury.projects` provider. The console and manager entry field consume the same completion definitions. Mercury does not infer another module's common values from command names.

## REQ-MERC-440 Frontend And Shortcut Entries

- The HV tile and `mercury.app.open` first execute `vulcan.app.show`. If the bus cannot show the frontend, fallback activation accepts only a `HistoryVulcan` process with a real main window, and cold start resolves only `HistoryVulcan.exe`.
- `mercury.shortcut.open` and `mercury.shortcut.add` each declare one required `path` parameter at `Position=0`. `.lnk` files are resolved before opening; direct files and directories are also accepted. Missing sources, unresolved links, and missing targets return explicit failures.
- `mercury.shortcut.add` persists the normalized source path through `mercury.shortcut.open`, derives a stable filename label, quotes command text with `CommandParser`, and deduplicates by normalized command text. Future dock drag-and-drop must call this same registration path.
- Dock command normalization collapses whitespace only outside quoted arguments. Quotes, escape runs, and whitespace inside a quoted path are preserved byte-for-byte so paths such as `"C:\A  B.lnk"` remain executable.
- Acceptance is the 24-command Smoke catalog plus direct-file, `.lnk`, failure, label, quoting, deduplication, focused `go `, and HV executable-resolution regressions.
