# HistoryMercury Project Overview

## Purpose

HistoryMercury provides the HistoryVulcan desktop project dock, its managed Explorer shortcut folder, and project-level command access for the `C:\OneHistory\HistoryVesta` library.

## Current State

- Formal snapshot: `HistoryMercury 4.5.2` in `z-HistoryMercury`.
- Current source: `HistoryMercury 4.5.2` in `b-Code-MercuryDock` (owns global shortcut host, double-slash wake, command workbench UI, and the Vulcan-aligned dock manager page for HistoryVulcan 3.11.1).
- 4.5.1 收敛外壳侧的写入与通知：注册与快捷方式同步都幂等，`SHCNE_ASSOCCHANGED` 只用于命名空间项自身的变化，
  目录内容变化定点通知；服务进程与界面进程都跟随 `state.json`，不再把对方的写入读成用户增删。见 REQ-MERC-451。
- 4.5.2 修正宿主引用面与建界面顺序：模块默认编译到已发布的 z 宿主快照，`CreateUi` 先建桌面坞再挂宿主内扩展，
  任一扩展失败不再带走桌面坞。见 REQ-MERC-452 / DEC-013。
- Completion resolves focused shorthand before loading details: under Mercury focus, `go ` loads `mercury.go`, then advances through registered domain, class, method, and parameter metadata. Mercury project values come from the registered `mercury.projects` provider in both the console and manager entry field.
- The HV tile and `mercury.app.open` use `vulcan.app.show` with a strict `HistoryVulcan.exe` cold-start fallback. `//` remains bound only to `vulcan.app.focusconsole`.
- `mercury.shortcut.open <path>` opens `.lnk`, file, or directory targets; `mercury.shortcut.add <path>` stores the same positional command as a deduplicated dock entry for future drag-and-drop reuse.
- Candidate package: `b-Publish/current/HistoryMercury` matches the formal 4.5.2 snapshot.
- The 4.5.0 manager page uses Shell dynamic resources, a unified dock-entry table, responsive compact details, a single add menu, and CommandBus-backed write actions.

## Scope

The module lists active project directories, maintains project and command entries in the dock, resolves Windows shortcut files, exposes the `mercury` command contract, registers the `HistoryVesta 项目` Explorer entry, hosts `GlobalShortcutService` / double-slash registration, and attaches the command catalog/detail workbench to the Vulcan shell. It uses HistoryVulcan public module, UI, and command contracts without duplicating the host command bus.
