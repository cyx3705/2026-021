# MercuryDock V3.3.0：History 迁移收尾

## 目的

完成 ActiveDock 迁入 HistoryMercury 后遗留的身份、数据目录、Explorer 入口和项目元数据治理。模块名称保持 `MercuryDock`，宿主统一称为 `HistoryVulcan`，项目库统一称为 `HistoryVesta`。

## 运行时迁移

- 新状态、图标缓存、桌面层日志和 Explorer 备份统一写入 `%APPDATA%\HistoryVulcan\MercuryDock`。
- 新快捷方式槽为 `%APPDATA%\HistoryVulcan\Modules\MercuryDock\快捷方式`，资源管理器入口显示为“HistoryVesta 项目”。
- 新状态不存在时，先迁移 `%APPDATA%\OneHistoryStudio\MercuryDock\state.json`，再回退迁移更早的 `ActiveDock\state.json`；旧文件不删除。
- `ActiveDock.Managed` 仅作为旧注册表拥有标识兼容读取。新写入使用 `MercuryDock.Managed`，防止把用户自有 Explorer 项误当作模块项。
- 工作树配置优先读取 HistoryVulcan 的 `settings.json`，旧 OneHistoryStudio 配置只在新配置不可用时回退读取。

## 项目与发布治理

- `project.manifest.json`、根 README 和 `b-Office/current` 从 AIReady 模板实例化为 HistoryMercury 的现行合同。
- 模块清单移至 `b-Code-MercuryDock/module.manifest.json` 作为唯一源码；发布脚本由该清单构建候选包，不再从 `z-MercuryDock` 反向读取版本。
- `z-MercuryDock` 保持正式快照属性。本版本只生成候选包，不因代码变更自动覆盖正式槽。

## 兼容性

- 保持模块名 `MercuryDock`、`dock.*` 命令域、`mercury.dock.open`、`dock.manager` 和 Explorer CLSID 不变。
- 桌面入口从 `OHS` 改为 `HV`，打开行为不变。
- ActiveDock、OneHistoryStudio 和 OHS 只在历史资料或明确的迁移兼容代码中保留，不再作为新的写入或显示名称。

## 验收

1. 严格项目合同检查通过，且无模板占位符。
2. MercuryDock Smoke 断言 `3.3.0`、HistoryVulcan 快捷方式槽和“HistoryVesta 项目”。
3. Release build 与格式检查通过。
4. 候选包与源码清单版本一致，哈希完整，正式 `z-MercuryDock` 未被自动覆盖。
5. 正式提升后，重新加载模块会创建新快捷方式槽并把 Explorer 入口重定向到该槽。
