# MercuryDock 3.2.0 级联指令选择与无箭头建议框

承接 3.1.0：加入区的两个下拉框 ComboBox 在窄面板下换行截断、文本不垂直居中，
且下拉箭头+手动点击的交互不符合"输入即选"的预期。本版用自绘建议框彻底替换。

## 一、SuggestBox 控件（SuggestBox.cs）

无下拉箭头的建议输入框，TextBox + Popup + ListBox 自绘组合：

- **输入即弹**：文本变化（或获得焦点）时按当前输入过滤候选，向下自动弹出；
  无候选或失焦时收起。
- **导航键**：`Shift+W` 上、`Shift+S` 下（方向键同样可用）；
  `Tab`/`Enter` 确认高亮项；`Esc` 关闭。Shift+W/S 与输入大写 W/S 冲突，
  属约定取舍（可用 CapsLock 输入大写）。
- **样式随主题**：弹窗深色底圆角，选中项与主列表一致（淡黄底深字），
  文字颜色不写死、随选中态反色；输入框 `VerticalContentAlignment=Center`。
- 候选项为 `SuggestOption(Text, Display, Detail, IsBranch)`：
  Text 是确认后落入输入框的全文，Display 是弹窗段落显示，
  Detail 是弱化说明（摘要/子项数），IsBranch 表示还有下一级。

## 二、指令级联选择：域 → 类 → 方法

`CommandOptionTree`（MercuryDockAliasCommands.cs）把指令名按点号分层成树
（`mercury.dock.open` = 域 mercury → 类 dock → 方法 open），指令框按当前输入
逐级给出候选：

- 空输入列出根级域；选中分支确认后文本回填为 `mercury.`，立即展开下一级；
- 叶子（可执行指令）确认后弹窗关闭，全文落入输入框；候选带摘要说明；
- 同一节点既是指令又有下级时按分支处理（指令本身仍可手工输入全文）；
- 两段式存量指令（如 `dock.pin`）自然落在"域→方法"两级，与未来的
  三段式规范化（`mercury.dock.open`）兼容并存。

候选来源仍是服务侧 `command.list`（远程转发，含全模块指令），解析升级为
`ParseCommandCatalog`（名字/域/类/摘要四字段）；服务清单缺
`mercury.dock.open`（旧版模块未重载）时自动补入；服务不可达回退
`FallbackCommandCatalog`（常驻默认指令 + 16 条 dock.*，带摘要）。

## 三、加入区布局修复

- 指令框独占整行、参数框与"加入扩展坞"按钮同行（DockPanel），
  窄面板下不再换行截断；
- 所有输入框文本垂直居中（TextBox 的 VerticalContentAlignment，
  旧 ComboBox 可编辑模式下该属性不生效是"文字不居中"bug 的根源）；
- 参数框在 `mercury.dock.open` 下仍为项目名/编号候选（`Contains` 过滤，
  输入编号即可命中），确认即加入；其他指令自由输入；
- 指令叶子确认后焦点自动落到参数框；底部提示更新为新按键说明。

## 四、版本与烟测

3.1.0 → 3.2.0。烟测新增：`ParseCommandCatalog` 四字段解析、级联树断言
（根级分支/叶子、分支确认进入下一级、方法级全文与摘要、过滤段收缩、未知路径为空）。
