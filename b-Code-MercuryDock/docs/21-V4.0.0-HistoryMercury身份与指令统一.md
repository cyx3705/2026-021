# HistoryMercury 4.0.0 Identity And Command Cutover

## Scope

This version replaces the former `MercuryDock` module identity with `HistoryMercury`. `Mercury` is the source namespace and command domain. The former two-track command surface is replaced by one direct composition-root catalog.

## Identity Mapping

| Previous | 4.0.0 |
| --- | --- |
| module name `MercuryDock` | module name `HistoryMercury` |
| `MercuryDock.dll` / `.xml` | `HistoryMercury.dll` / `.xml` |
| `z-MercuryDock` | `z-HistoryMercury` |
| `%APPDATA%\HistoryVulcan\MercuryDock` | `%APPDATA%\HistoryVulcan\HistoryMercury` |
| `%APPDATA%\HistoryVulcan\Modules\MercuryDock\快捷方式` | `%APPDATA%\HistoryVulcan\Modules\HistoryMercury\快捷方式` |
| `MercuryDock.Managed` | `HistoryMercury.Managed` |

The former state folders and Explorer ownership markers are read-only migration inputs. The module never deletes them during migration.

## Command Mapping

| Previous | 4.0.0 |
| --- | --- |
| `dock.explorer` | `mercury.status` |
| `dock.explorerRegister` | `mercury.explorer.register` |
| `dock.explorerRemove` | `mercury.explorer.remove` |
| `dock.list` | `mercury.proj.list` |
| `mercury.dock.open` | `mercury.proj.open` |
| `dock.add` | `mercury.proj.add` |
| `dock.pin` / `dock.unpin` | `mercury.proj.pin` / `mercury.proj.unpin` |
| `dock.refresh` | `mercury.proj.refresh` |
| `dock.exclude` / `dock.include` | `mercury.proj.exclude` / `mercury.proj.include` |
| `dock.hide` / `dock.show` | `mercury.dock.hide` / `mercury.dock.show` |
| `dock.policy` | `mercury.dock.policy` |
| `dock.open` | `mercury.app.open` |
| `dock.usage` / `dock.forget` | `mercury.usage.list` / `mercury.usage.forget` |

This is a hard cut. No legacy command aliases are registered. All 17 current commands come from `MercuryCommandCatalog.Register` through `IModuleContext.RegisterCommands`; `ModuleInfo.MainClassType` is null to prevent a parallel reflection surface.

## Validation

The version gate requires Release build, smoke, formatting, project-contract validation, candidate package hash verification, and a formal-release check that `z-HistoryMercury` contains only the artifact pair, manifest, and `SHA256SUMS`. Runtime acceptance requires `module.list` to show `HistoryMercury 4.0.0` and `command.list` to list only the new `mercury` contract for this module.
